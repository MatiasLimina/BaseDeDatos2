# Tasks

> **Convenciones de ejecución**
> - Todos los comandos se ejecutan desde `TP8/`. PostgreSQL: **solo** `food_store_copia`, con `psql -X -w -h localhost -U postgres -d food_store_copia -v ON_ERROR_STOP=1` y `PGCLIENTENCODING=UTF8` (nunca `foodstore` ni `food_store`; nunca leer ni versionar `pgpass.conf`). SQLite: `sqlite3` ≥ 3.37.
> - **Escrituras en PostgreSQL** (crear la vista, preparar/restaurar C2 y C4): si la sesión del agente no tiene credencial (`fe_sendauth: no password supplied`), el agente deja el comando exacto y **el humano lo ejecuta**; el agente verifica después por MCP `postgres` (solo lectura). Marcadas con **[PG-escritura]**.
> - **Strict TDD**: cada script tiene un `tests/test_*.sh` escrito antes (RED: falla por archivo/objeto inexistente o aserción falsa; anotar el mensaje), luego GREEN, TRIANGULATE y REFACTOR. Los tests imprimen `test_x: OK` o `test_x: FALLA - motivo` y salen ≠ 0 en falla. Los tests de SQLite usan una copia temporal (`mktemp -d`), nunca `movil/foodstore_movil.db`.
> - **Modo aprendizaje**: las tareas marcadas **(humano)** las escribe el humano; el agente deja el andamiaje y el test, y después solo revisa.
> - **Bitácora**: al cerrar cada grupo, si hubo una interacción relevante con la IA (algo aceptado, corregido o descartado), agregar una fila a `docs/bitacora_ia.md` (formato de bitácora definido en design.md, Context).
> - **Commits**: uno por grupo, Conventional Commits en español, scope `tp8`; los ejecuta el orquestador. Sin `push` ni etiqueta hasta el grupo 12.
> - **Gobernanza MEDIUM**: en cada `CHECKPOINT` detenerse y exponer las decisiones no obvias antes de seguir.
